# Public release rights audit

This is a practical release boundary, not a legal opinion. The goal is to publish the research substance without concealing provenance or reproducing restricted material.

## Safe public core used here

| Material | Release approach |
| --- | --- |
| Reported company financial facts | Narrow manual extraction from cited public issuer filings |
| Ratios, indexes and growth rates | Original calculations from the public-filing dataset |
| Charts and report prose | Original presentation and analysis created for this repository |
| Methodology and code | Original work under the repository licence |
| Synthetic fixture | Retained only as a small test CSV; no longer used as a showcase visual |

## Keep private unless separately cleared

| Material | Reason |
| --- | --- |
| Commercial-terminal exports and screenshots | Access does not imply public redistribution rights |
| A chart redrawn from restricted values | A new visual style does not change the source or permission basis |
| Proprietary estimates, classifications or comparison screens | May embody protected selection, methodology, or contract-restricted data |
| Downloaded reports or branded interface elements | Public linking is safer than republishing the files or visual design |
| Market-price history from an unclear web/API licence | Public accessibility alone is not a redistribution licence |

## What can be reconstructed next

- Additional cash-flow years from each issuer filing, with row-level source mapping.
- Peer operating comparisons independently extracted from each peer’s own filings, after normalizing definitions.
- An event timeline based on company announcements and regulatory filings.
- Market-return analysis only from a source whose licence expressly permits public redistribution, or with written permission.

GitHub requires users to have the right to post third-party content and allows public repositories to be viewed and forked. That makes a source licence or other documented release basis important even when a file is freely accessible online. See the [GitHub Terms of Service](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service) and this repository’s [data policy](DATA-POLICY.md).

Indian copyright guidance also treats sufficiently original tables, compilations and databases as potentially protected literary works. The public dataset therefore avoids copying a source table wholesale: it uses a limited selection of reported facts, a new schema, row-level citations, original calculations and original visual design. See the [Copyright Office’s literary-works guidance](https://copyright.gov.in/Documents/Public_Notice_inviting_reviews_and_comments_of_stakeholders_on_draft_guidelines/Literary_Work.pdf). Contractual restrictions can be broader than copyright, which is why restricted subscription inputs remain outside the public workflow.
